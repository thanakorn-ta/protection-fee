# Protection Fee — ตารางสรุปการใช้รถคุ้มครอง

โปรเจกต์สำหรับติดตามและสรุป **ค่ารถคุ้มครอง (Protection fee)** ที่ใช้เวลาทีมเข้าทำงานบนป้ายโฆษณาในเขตทางพิเศษ (ทางด่วน) ได้แก่ป้าย **Flyover 2.0** และ **Gateway Billboard** ของ EXAT และ BEM แยกรายเดือน

## เว็บแอป

เว็บแอปสร้างด้วย **Google Apps Script** อ่าน/เขียนข้อมูลลง Google Sheet โดยตรง ไม่ต้องมีเซิร์ฟเวอร์ ใช้ได้ทั้งมือถือและคอมพิวเตอร์

**ใช้งานได้ที่:** [protectionfee.vercel.app](https://protectionfee.vercel.app) (หน้าเว็บบน Vercel เรียก Apps Script ตรง ถ้าไม่ได้จะผ่าน /api/rpc — ดู [Deploy to Netlify](#deploy-to-netlify)) หรือเปิด Apps Script ตรง ๆ ที่ [web app](https://script.google.com/macros/s/AKfycbyyfHHkyzEEIcIKX5VGJL3l_tIcUVR1Og8vzQO7Ac2eo278zbDBkGisGhg-FsoosgnxWQ/exec)

### ไฟล์ (เวอร์ชัน Apps Script)

```
apps-script/
├── Code.gs          # ฝั่งเซิร์ฟเวอร์: สมัครสมาชิก, เข้าสู่ระบบ, เขียนข้อมูลลงชีท
├── Index.html       # หน้าเว็บทั้งหมด (HTML + CSS + JS)
└── appsscript.json  # การตั้งค่าโปรเจกต์ Apps Script
```

### ติดตั้ง

1. **แปลงไฟล์เป็น Google Sheets** — ไฟล์ฐานข้อมูลปัจจุบันเป็น `.xlsx` ซึ่ง Apps Script เขียนไม่ได้
   เปิดไฟล์ใน Google Sheets → **ไฟล์ → บันทึกเป็น Google ชีต** แล้วใช้ไฟล์ใหม่นั้นเป็นฐานข้อมูล
2. ในไฟล์ Google Sheets ใหม่ ไปที่ **ส่วนขยาย → Apps Script**
3. คัดลอกเนื้อหา `Code.gs` และสร้างไฟล์ HTML ชื่อ `Index` แล้ววางเนื้อหา `Index.html`
4. เปิด **การตั้งค่าโปรเจกต์ → แสดงไฟล์ appsscript.json** แล้ววางเนื้อหา `appsscript.json`
5. **ทำให้ใช้งานได้ → การทำให้ใช้งานได้รายการใหม่ → เว็บแอป**
   - ดำเนินการในฐานะ: **ฉัน**
   - ผู้ที่มีสิทธิ์เข้าถึง: **ทุกคน** (หรือเฉพาะคนในองค์กร ถ้าทุกคนมีบัญชี Google ของบริษัท)
6. อนุญาตสิทธิ์ แล้วเปิดลิงก์เว็บแอป → **สมัครสมาชิกคนแรก** (จะเป็นผู้ดูแลระบบ)

> `Code.gs` ตั้ง `CONFIG.SPREADSHEET_ID` เป็นชีทจริงไว้แล้ว — ใช้ได้ทั้งสคริปต์ที่ผูกกับชีทและแบบ standalone (เปลี่ยนได้ด้วย Script Property `SPREADSHEET_ID`)
>
> ใช้ [clasp](https://github.com/google/clasp) ได้: `clasp clone <scriptId> --rootDir apps-script` แล้ว `clasp push`

### การทำงานกับชีท

- ระบบหาแท็บ EXAT / BEM / DataBase เองจาก**หัวคอลัมน์** ไม่ต้องตั้งชื่อแท็บ (ถ้าต้องการกำหนดเอง แก้ `CONFIG.SHEETS` ใน `Code.gs`)
- แถวใหม่เขียนต่อจาก**แถวล่าสุดที่มีวันที่** — ถ้ามีเลขลำดับเตรียมไว้ล่วงหน้าจะใช้เลขนั้น และคัดลอกรูปแบบเซลล์จากแถวก่อนหน้า
- คอลัมน์ เดือน / วันที่ เขียนเป็นวันที่หรือข้อความ (เช่น `Sep-26`, `1 ก.ย. 69`) ตามรูปแบบของแถวก่อนหน้า
- ระบบสร้างแท็บเพิ่ม 2 แท็บ:
  - `Users` — บัญชีผู้ใช้ (รหัสผ่านเก็บเป็น hash + salt ไม่เก็บรหัสจริง)
  - `AuditLog` — บันทึกว่าใครเพิ่มข้อมูลแถวไหน เมื่อไร
- เข้าสู่ระบบผิด 5 ครั้งจะถูกล็อก 15 นาที / session หมดอายุใน 6 ชั่วโมง

### โครงสร้างข้อมูล

#### 1. DataBase — Flyover 2.0 / Gateway Billboard

ข้อมูลหลักของป้ายแต่ละจุด ใช้อ้างอิงตอนบันทึกการใช้รถคุ้มครอง

| คอลัมน์ | ความหมาย |
|---|---|
| Pack | กลุ่ม/แพ็กของป้าย (1, 2, 3, ...) |
| ป้าย | รหัสป้าย เช่น `1.1`, `2.3` |
| Media Site | ประเภทสื่อ เช่น `Flyover 2.0 BECL`, `Flyover 2.0 EXAT`, `Gateway BEM`, `Gateway EXAT` |
| บริเวณ | ตำแหน่งป้าย (ไทย / อังกฤษ) |
| เขตพื้นที่ | ผู้ดูแลทางพิเศษ (EXAT / BEM) |
| เขตพื้นที่ (สายทาง) | สายทางด่วน เช่น ศรีรัช, ฉลองรัช, เฉลิมมหานคร |
| Size. | ขนาดป้าย เช่น `3 x 14 m.` |
| จำนวนป้าย | จำนวนหน้าป้าย |
| ถนน | ถนนที่ตั้งป้าย |
| เขตพื้นที่ กทม. | เขตของกรุงเทพฯ |
| จุดนัดพบ | ด่าน/จุดนัดพบกับรถคุ้มครอง |
| อยู่ในพื้นที่ สน. | สถานีตำรวจในพื้นที่ |

#### 2. รถคุ้มครอง EXAT (ทดรองจ่าย)

บันทึกการใช้รถคุ้มครองของ **การทางพิเศษแห่งประเทศไทย (EXAT)** จ่ายแบบทดรองจ่าย

| คอลัมน์ | ความหมาย |
|---|---|
| ลำดับ | เลขรายการ |
| เดือน | เดือนที่ใช้ (เช่น `May-22`, `Sep-26`) |
| วันที่ | วันที่เข้างาน (พ.ศ.) |
| รถคุ้มครอง | หน่วยงานที่ให้บริการรถคุ้มครอง |
| สายทาง | สายทางด่วน |
| โครงการ | Media Site ของป้าย |
| สถานที่ | ป้าย / จุดที่เข้าทำงาน |
| ประเภทงาน | เช่น ติดตั้งสินค้า, ตรวจสอบโครงสร้าง, แก้ไขระบบไฟฟ้า |
| ผู้เข้างาน | ผู้รับผิดชอบหน้างาน |
| ค่าอาหาร/รถคุ้มครอง | ค่าใช้จ่ายต่อครั้ง (บาท) — ถ้าเข้าหลายจุดในวันเดียวกัน จะคิดครั้งเดียว จุดที่เหลือเป็น `0` |

#### 3. รถคุ้มครอง BEM (เปิด PR)

บันทึกการใช้รถคุ้มครองของ **บมจ.ทางด่วนและรถไฟฟ้ากรุงเทพ (BEM)** จ่ายแบบเปิด PR

คอลัมน์เหมือนกับตาราง EXAT แต่มีคอลัมน์ต่างกันดังนี้

| คอลัมน์ | ความหมาย |
|---|---|
| ค่ารถคุ้มครอง | วิธีคิดค่ารถ เช่น `คิดค่ารถ 1 คืน` |
| การชำระเงิน | สถานะการชำระเงิน เช่น `เรียบร้อย` |

## การใช้งาน

1. ทุกครั้งที่ทีมเข้างานบนป้ายในเขตทางด่วน ให้บันทึกผ่านเว็บแอป หน้า **บันทึกการใช้รถ** (เลือก EXAT หรือ BEM)
2. เลือก **สถานที่** จากรายการ — ระบบเติมสายทางและโครงการจากตาราง DataBase ให้
3. เข้าหลายจุดในวันเดียวกัน (EXAT): บันทึกทุกจุด แต่คิดค่าใช้จ่ายจุดแรก จุดที่เหลือใส่ `0`
4. ตาราง BEM: อัปเดต **การชำระเงิน** ในชีทเมื่อ PR ได้รับการจ่ายแล้ว

## มือถือและคอมพิวเตอร์

ใช้ได้บน **iPhone / iPad (Safari)**, **Android (Chrome)**, **Windows (Chrome / Edge)** และ **macOS (Safari / Chrome)** หน้าจอปรับตามความกว้าง 360 px ขึ้นไปจนถึงจอคอมพิวเตอร์

- ไม่มีการเลื่อนหน้าแนวนอน — ตารางกว้างเลื่อนในกรอบของตัวเอง ปุ่มและช่องกรอกสูงอย่างน้อย 44 px
- ช่องกรอกใช้ตัวอักษร 16 px บนมือถือ (iOS ไม่ซูมหน้าเองตอนแตะ) รองรับรอยบาก / แถบ Home (safe area) และใช้ `100dvh`
- วันที่ / เวลาใช้ตัวเลือกของเครื่อง แนบภาพ / วิดีโอได้ทั้งจากกล้องและคลังภาพ
- ปฏิทินบนมือถือ: แตะที่วันเพื่อจองได้เลย (คอมพิวเตอร์มีปุ่ม + เมื่อชี้เมาส์ แท็บเล็ตแสดง + เสมอ)

### ติดตั้งเป็นแอป (PWA)

เปิด [protectionfee.vercel.app](https://protectionfee.vercel.app) แล้ว
- **iPhone / iPad:** Safari → ปุ่มแชร์ → **เพิ่มไปยังหน้าจอโฮม**
- **Android:** Chrome → เมนู ⋮ → **ติดตั้งแอป** / เพิ่มลงในหน้าจอหลัก
- **Windows / macOS:** Chrome หรือ Edge → ไอคอนติดตั้งในช่องที่อยู่เว็บ

แอปเปิดเต็มจอพร้อมไอคอน (`public/manifest.webmanifest`, `public/icons/` — สร้างใหม่ได้ด้วย `scripts/make-icons.ps1`) **ไม่มี service worker** ข้อมูลมาจากเซิร์ฟเวอร์ทุกครั้ง จึงไม่มีข้อมูลเก่าค้าง (ต้องต่ออินเทอร์เน็ต) — ติดตั้งได้เฉพาะเวอร์ชันบน Vercel / Netlify เพราะหน้า Apps Script เปิดใน iframe ของ Google

## Deploy to Netlify

ตอนนี้ระบบจริงอยู่บน Vercel — โค้ดเตรียมไว้ให้ย้ายไป Netlify ได้โดยไม่ต้องแก้

1. Netlify → **Add new site → Import an existing project** → เลือก GitHub `thanakorn-ta/protection-fee` สาขา `main`
2. Netlify อ่าน [`netlify.toml`](netlify.toml) เอง: build `npm run build`, publish `.next`, Node 20 และใช้ Next.js Runtime ให้อัตโนมัติ
3. **Environment variables** (Site configuration → Environment variables) — ไม่บังคับ ค่าเริ่มต้นใช้ได้เลย:

   | ตัวแปร | ค่า | ใช้ทำอะไร |
   |---|---|---|
   | `APPS_SCRIPT_URL` | URL `/exec` ของ Apps Script | ค่าเริ่มต้นเป็นเว็บแอปจริงอยู่แล้ว |
   | `RPC_MODE` | `direct` (ค่าเริ่มต้น) หรือ `proxy` | `direct` = เบราว์เซอร์เรียก Apps Script ตรง ไม่ติดเวลาจำกัดของฟังก์ชัน Netlify (~10 วินาที) ถ้าเรียกไม่ได้จะผ่าน `/api/rpc` เอง |
   | `SPREADSHEET_ID` | ID ของ Google Sheet | เฉพาะแอป Next.js แบบเข้าสู่ระบบด้วย Google (ยังไม่ได้ใช้) |

   ห้ามตั้ง `GOOGLE_CLIENT_ID` + `GOOGLE_SERVICE_ACCOUNT_JSON` + `SESSION_SECRET` พร้อมกัน ถ้ายังไม่พร้อมใช้แอปแบบ Google Sign-In — `middleware.ts` จะเปลี่ยนหน้าแรกไปใช้แอปนั้นแทน
4. Deploy แล้วเปิดเว็บ ตรวจหน้าเข้าสู่ระบบ / ตารางจอง / File Accrue
5. **ลิงก์ในอีเมลรีเซ็ตรหัสผ่าน:** ตั้ง Script Property `APP_URL` ใน Apps Script เป็นโดเมน Netlify ใหม่ (เช่น `https://<ชื่อเว็บ>.netlify.app/`) — ค่าเริ่มต้นชี้ไปที่ Vercel

**งานตั้งเวลา (ส่ง File Accrue / File Clear อัตโนมัติ)** อยู่ใน **Apps Script** (ตัวตั้งเวลา `accrueMonthlyJob` ทุกวัน 09:00) ไม่ขึ้นกับ Vercel หรือ Netlify — ย้ายโฮสต์แล้วยังส่งตามปกติ ไม่ต้องตั้ง Scheduled Functions ของ Netlify

โค้ดที่ผูกกับ Vercel มีแค่ `vercel.json` และ `export const maxDuration` ใน `app/api/rpc/route.ts` (Netlify ไม่อ่าน ไม่มีผล)
